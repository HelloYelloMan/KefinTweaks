//!PARAM analog_width
//!DESC Analog sampling grid - width (0 = auto, isotropic from analog_height)
//!TYPE float
//!MINIMUM 0
//!MAXIMUM 2048
352.0

//!PARAM analog_height
//!DESC Analog sampling grid - height
//!TYPE float
//!MINIMUM 48
//!MAXIMUM 1152
480.0

//!HOOK MAIN
//!BIND HOOKED
//!WIDTH analog_width analog_width ! OUTPUT.width OUTPUT.height / analog_height * * +
//!HEIGHT analog_height
//!DESC analog resolution (box downscale)

// Resizes MAIN to an analog sampling grid. Both dimensions are set from
// shader-opts - libplacebo's size expressions accept parameter names, so the
// WIDTH and HEIGHT directives can reference them directly and no
// per-resolution file is needed.
//
// Not a plain HOOKED_tex fetch: that is a single bilinear tap, which throws
// away most of the source and aliases badly at these ratios. This box-averages
// the real footprint - ceil(ratio) samples per axis, at least one per source
// texel, capped at 8.
//
// Averaging happens in the encoded (gamma) domain, not linear light, because
// MAIN is still in the source transfer function here - both later shaders do
// their own sRGB-to-linear in a MAIN_RGB pass. Averaging signal levels is what
// an analog low-pass does to a video signal. Linearising first would be right
// for a resize destined for display; it is wrong for bandwidth limiting.
//
// Touches nothing aspect-related. Display aspect comes from the container, not
// from this texture's dimensions, so 4:3 and 16:9 both stay correct.
//
// The two params stay TYPE float rather than CONSTANT because libplacebo
// resolves them inside the WIDTH / HEIGHT size expressions, which works as
// written under libplacebo 7.360. Do not change without retesting that the
// shader still loads.
//
// ---------------------------------------------------------------------------
// analog_width = 0: isotropic ("clean scale") mode
// ---------------------------------------------------------------------------
// Horizontal and vertical are not the same kind of quantity. The vertical axis
// is genuinely quantised - a CRT raster has a discrete, countable number of
// scanlines and there is no picture information between them. The horizontal
// axis is not: the beam sweeps continuously, and its only limits are signal
// bandwidth and spot size, both of which are LOW-PASS FILTERS, not sample
// grids. Picking analog_width is therefore a modelling compromise, and picking
// it badly shows up as visible texel edges that no real tube ever had.
//
// Horizontal resolution is properly measured in TV lines - cycles resolvable
// across one picture HEIGHT of width, which makes it comparable to the line
// count. For a picture of display aspect A with N horizontal samples:
//
//     TVL = N / A
//
// Set N = A * analog_height and it collapses:
//
//     TVL = (A * analog_height) / A = analog_height
//
// So scaling uniformly makes TVL equal the line count, at ANY aspect ratio,
// with no magic constant to choose. 4:3 -> 640x480, 16:9 -> 853x480, and both
// are 480 TVL. That is an ISOTROPIC display - equally sharp on both axes -
// which is roughly right for a good consumer tube fed RGB (450-550 TVL at 480
// lines) and is the mode to use when there is no NTSC filter in the chain.
//
// It is WRONG for composite. NTSC over composite is ~330 TVL against 480
// lines: genuinely softer horizontally than vertically, and that asymmetry is
// part of why composite looks like composite. Leave analog_width explicit
// (352) for any profile that runs the NTSC shader.
//
// Bonus: uniform scaling makes the box footprint square, so the FILTER is
// isotropic too. 1920x1080 -> 352x480 averages 6 taps horizontally against 3
// vertically; -> 853x480 is 3 and 3.
//
// A is taken from OUTPUT, i.e. target_size, documented as "the size in pixels
// of the visible part of the scaled (and possibly cropped) image" - that is the
// picture rectangle after aspect correction, so its ratio is the DISPLAY aspect
// and not the storage aspect. This matters: a 720x480 NTSC DVD has a storage
// ratio of 1.5 and a DAR that may be anything from 1.333 to 1.85. Deriving the
// width from HOOKED_size would be wrong for every anamorphic source.
//
// TWO ASSUMPTIONS, both unverified at the time of writing - see the note in
// the session log if this ever misbehaves:
//
//   1. `!` in a szexpr is logical NOT (0 -> 1, non-zero -> 0). The mpv manual
//      lists it as an operator but does not define it. The whole expression is
//      a select: `aw + !aw * auto` returns aw when aw > 0 and auto when aw = 0.
//      If `!` means something else, manual widths will still work and auto mode
//      will produce a wrong size rather than failing loudly.
//   2. OUTPUT.width / OUTPUT.height equals the display aspect. It should, given
//      the target_size wording, but --keepaspect=no, panscan and video-zoom all
//      change the picture rectangle and would skew it.
//
// The GLSL below recomputes the same width to derive `ratio`. libplacebo rounds
// the szexpr result to an integer texture size and this does not, so the two
// can disagree by a fraction of a texel - about 0.04% at 1080p, which moves no
// tap into a different source pixel.


vec4 hook()
{
    // Must mirror the WIDTH szexpr above. analog_width = 0 means "derive an
    // isotropic width from analog_height and the display aspect".
    float dar   = target_size.x / target_size.y;
    float width = analog_width > 0.0 ? analog_width : analog_height * dar;

    vec2 target = vec2(width, analog_height);
    vec2 ratio  = HOOKED_size / target;
    ivec2 taps  = clamp(ivec2(ceil(ratio)), ivec2(1), ivec2(8));

    vec4 sum = vec4(0.0);
    for (int y = 0; y < taps.y; y++) {
        for (int x = 0; x < taps.x; x++) {
            vec2 o = (vec2(float(x), float(y)) + 0.5) / vec2(taps) - 0.5;
            sum += HOOKED_tex(HOOKED_pos + o * ratio * HOOKED_pt);
        }
    }
    return sum / float(taps.x * taps.y);
}
